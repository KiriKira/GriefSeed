# 请求预算及验证边界

以下是单 owner、一个 Homura、一个 Madoka、一个冷备 Worker、无通话/短信、稳定网络的预算情景，不是平台上限。
仅适用于支持本批能力协商的手机；旧手机继续 HTTP，其周期轮询会明显增加用量。

| 来源 | 一天情景中的操作 | Workers 请求 | DO 请求/消息 |
|---|---:|---:|---:|
| 两端控制 WebSocket | 各建立一次，稳定连接 | 2 | 2 个握手 |
| 网关心跳 | 60 秒一次 | 0 | 1,440 条消息 |
| 网关能力重申 | 每小时两项 | 0 | 48 条消息 |
| 两端令牌刷新 | 各 15 分钟一次，原连接内完成 | 0 | 192 条消息 |
| 网关公开 capabilities | 每小时一次 | 24 | 0，Worker 直接回答 |
| 非活动冷备探测 | 主节点健康时暂停 | 0 | 0 |
| 空呼叫/命令/事件轮询 | 连接内缓存，被状态通知失效 | 稳态 0 | 稳态 0 |

合计约 26 次 Workers 请求和 1,680 条 DO 入站消息，加上握手及首次同步。按每 20 条消息计一次请求作预算，约百次 DO 请求量级。
初次配对、管理操作、首次补拉、客户端具体启动顺序及计费取整会增加用量；不能将本表当实测账单。
协议 ping 不刷新业务租约，不能拿其免费特性替代续租。

主节点模式还包含健康检查、UI 拉取、短信与备份，不能套用冷备数值。
活动通话：每端每 5 秒 control/calls、通常每 2 秒媒体状态读取，约每小时 2,520 条消息/端，另加协商/候选/事件。
每条消息都会重新鉴权。丢线转 HTTP 后，Workers 请求重新计入；副作用仍用相同 operation_id 及 durable ACK。

SQLite 写入必须另计：心跳写 sequence、SIM 事实和能力新鲜度；刷新写会话代际；普通设备操作写日计数。
表达式索引也可能影响计费写入，源码 SQL 次数不能直接当平台写入行数。alarm 检查截止时间并恢复 outbox；空闲时只安排已有任务所需的 alarm。
应在真实部署分别记录 Workers 请求、DO 入站消息/请求、唤醒时长、SQL rows read/written、alarm 和推送/撤销重试。

本地证据包括：一日等量的 2,880 次空命令轮询没有增加网络 RPC、快照不替代 5 秒续租、限额后保留结束 CAS 读取及取消、
无推送时主节点失败后同轮激活冷备。没有运行真实 Cloudflare 24 小时测量。

重连情景另列：每分钟重连一天是 1,440 次握手/设备/节点，仍不是上限。客户端指数退避加 jitter，稳定 60 秒才重置；
Retry-After 不被网络切换或 token 更新缩短。连接数限流仅退避握手，不禁止 HTTP 续租。
被窃/已吊销的真实签名仍会进入 DO；平台 1027 或全局额度耗尽仍可阻断结束确认，保留预算不能消除此边界。
